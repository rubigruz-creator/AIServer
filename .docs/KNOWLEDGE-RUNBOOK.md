# Регламент: как «учить» чат-бота автосервиса

> Простая инструкция для администратора.  
> Читать с начала один раз, потом пользоваться таблицей «когда что делать».

---

## Главное за 30 секунд

1. **Бот не учится сам.** Вы добавляете тексты в файлы на сервере (или на ПК → GitHub → сервер).
2. **Два места с знаниями:**
   - файлы в папке `prompts/knowledge/` — факты и ответы на вопросы;
   - файл `prompts/truck-service-system.txt` — как вести диалог и оформлять заявку.
3. **После любой правки** на сервере нужно запустить **2–3 команды** (см. раздел 6).

Чат на сайтах сам по себе каждый день ничего не обновляет — только отвечает по тому, что вы уже загрузили.

---

## Зачем это нужно

| Без обучения | С обучением |
|--------------|-------------|
| Бот умеет только записать на сервис | Бот ещё отвечает: часы, услуги, «есть ли выезд» |
| Может выдумать цену | Говорит честно: «уточним после осмотра» |
| Одинаково для всех сайтов | Можно дописать FAQ под ваши услуги |

**Обучение здесь = правка текстовых файлов**, не «скачать мозги из интернета».

---

## Какие файлы за что отвечают

```
prompts/
├── truck-service-system.txt     ← КАК разговаривать (заявка, порядок вопросов, «ЗАЯВКА СОЗДАНА»)
└── knowledge/
    ├── services.md              ← ЧТО делаем / не делаем, марки, режим работы
    ├── faq.md                   ← Вопрос — ответ (самый удобный файл для вас)
    ├── README.md                ← подсказка для разработчика (можно не трогать)
    └── sites-scraped.md         ← черновик с сайтов (появляется после скрейпа; проверить руками)
```

### Когда какой файл трогать

| Вы хотите… | Редактируйте |
|------------|--------------|
| Изменить порядок вопросов, правила заявки, примеры строки `ЗАЯВКА СОЗДАНА` | `truck-service-system.txt` |
| Добавить услугу, часы, «не делаем выезд» | `knowledge/services.md` |
| Ответ на частый вопрос («сколько стоит ТО?») | `knowledge/faq.md` |
| Подтянуть текст с сайта | скрипт скрейпа → проверить → перенести в `faq.md` / `services.md` |

**Не плодите лишние файлы.** Лучше дописать `faq.md`, чем создавать `faq-2.md`.

---

## Что НЕ надо делать

1. **Не кладите в файлы** пароли, ключи, `.env` — только про автосервис.
2. **Не копируйте в FAQ** телефоны и имена клиентов из диалогов — это личные данные.
3. **Не публикуйте** `sites-scraped.md` без проверки — там мусор с меню сайта и старые цены.
4. **Не выдумывайте точные цены** в текстах, если вы их не проверили у мастера.
5. **Не пропускайте** команды после правки (`model-create` и `knowledge-index`) — иначе бот отвечает по-старому.
6. **Не ломайте** строку заявки. В конце диалога должна быть **ровно одна** строка вида:  
   `ЗАЯВКА СОЗДАНА: Имя: ..., Телефон: ..., ...`  
   (без кавычек и без лишего текста вокруг).
7. **Не делайте** файлы знаний на 20 страниц — на слабом сервере бот путается. Короткие блоки + FAQ.
8. **Не коммитьте в GitHub** файл `.env` и экспорт диалогов `feedback-export.json`.

## Когда что делать (расписание)

| Как часто | Что делать | Зачем |
|-----------|------------|--------|
| **По необходимости** | Правка `faq.md` / `services.md` + команды из раздела 6 | Новая услуга, сменили часы, бот ответил неправильно |
| **Раз в 1–2 недели** | Скрейп сайтов (раздел 5) + ваша проверка | Подтянуть тексты с gortruck.ru и др. |
| **Раз в месяц** | Разбор диалогов в `/intake/admin` (раздел 7) | Узнать, что клиенты спрашивают чаще всего |
| **Каждый день** | Ничего | Бот работает сам |

## Раздел 1. Простое добавление ответа (самый частый случай)

**Пример:** клиенты спрашивают «работаете ли в субботу?», бот отвечает криво.

### Шаги

1. Откройте на сервере (или на ПК, потом `git push`):
   ```
   prompts/knowledge/faq.md
   ```
2. Добавьте блок (скопируйте стиль других вопросов):

   ```markdown
   **Работаете ли в субботу?**  
   Да, суббота с 9:00 до 15:00. Воскресенье — выходной.
   ```

3. Сохраните файл.
4. На сервере выполните **раздел 6** (три команды).
5. Откройте чат на сайте и задайте тот же вопрос — проверьте ответ.

**Зачем два шага (файл + команды):**  
файл — это «учебник»; команды «загружают» его в бота и в поиск RAG.

---

## Раздел 2. Изменить услуги или режим работы

1. Файл: `prompts/knowledge/services.md`
2. Поправьте списки «Что делаем» / «Что не делаем» / часы.
3. Раздел 6 на сервере.
4. Проверка в чате.

---

## Раздел 3. Изменить сценарий заявки (редко)

**Только если** нужно поменять порядок полей, правила про телефон или формат строки `ЗАЯВКА СОЗДАНА`.

1. Файл: `prompts/truck-service-system.txt`
2. Правьте осторожно, короткими фразами.
3. Раздел 6.
4. **Обязательно** пройдите тест-заявку с телефоном до строки `ЗАЯВКА СОЗДАНА: ...`

---

## Раздел 4. Где править: ПК или сервер

### Вариант А — через GitHub (удобно)

1. На ПК в `C:\Users\USER\AIServer` правите `prompts/knowledge/faq.md`.
2. В PowerShell:
   ```powershell
   cd C:\Users\USER\AIServer
   git add prompts/knowledge/faq.md
   git commit -m "FAQ: суббота"
   git push origin main
   ```
3. На сервере:
   ```bash
   cd /root/AIServer
   git pull
   # раздел 6
   ```

### Вариант Б — прямо на сервере

```bash
nano /root/AIServer/prompts/knowledge/faq.md
# сохранить: Ctrl+O, Enter, Ctrl+X
# раздел 6
```

## Раздел 5. Подтянуть текст с ваших сайтов (раз в 1–2 недели)

**Зачем:** не перепечатывать вручную всё с сайта — скрипт сделает черновик. **Вы обязаны проверить глазами.**

### Шаги

1. При необходимости допишите адреса в `scripts/knowledge-urls.txt` (только **свои** сайты).
2. На сервере:
   ```bash
   cd /root/AIServer
   ./scripts/knowledge-scrape.sh
   ```
3. Откройте черновик `prompts/knowledge/sites-scraped.md`.
4. **Вы:** удалите мусор (меню, «главная», старые акции), перенесите полезное в `faq.md` или `services.md`.
5. Файл `sites-scraped.md` в RAG по умолчанию **не используется** — так безопаснее.
6. Раздел 6.

**Не надо:** запускать скрейп каждый день — достаточно после обновления сайта.

---

## Раздел 6. Команды после ЛЮБОЙ правки текстов (обязательно)

Выполняйте **на сервере**, из папки проекта:

```bash
cd /root/AIServer

# 1) Обновить поиск по базе знаний (RAG)
./scripts/knowledge-index.sh

# 2) Обновить «вшитый» промпт модели
./scripts/model-create.sh

# 3) Обновить виджет на сайтах (если меняли embed/chat.js)
./scripts/widget-deploy.sh
```

Если правили **только** `faq.md` или `services.md`, пункт 3 можно пропустить.

**Если скрипт ругается на `bash\r`:**

```bash
sed -i 's/\r$//' /root/AIServer/scripts/*.sh
chmod +x /root/AIServer/scripts/*.sh
```

**Если `knowledge-index.sh` ошибка 401:** проверьте пароль в `.env` → `INTAKE_ADMIN_PASSWORD` (тот же, что для входа в `/intake/admin`).

### Быстрая проверка

1. https://agent.remont-gazon.ru/embed/chat.html  
2. Вопрос из FAQ — ответ должен совпадать с текстом.  
3. Оформите тест-заявку с телефоном — в конце одна строка `ЗАЯВКА СОЗДАНА: ...`.

---

## Раздел 7. Раз в месяц — учиться на диалогах клиентов

**Зачем:** увидеть реальные вопросы, которые вы ещё не добавили в FAQ.

1. Откройте: https://agent.remont-gazon.ru/intake/admin  
2. Смотрите диалоги **без заявки**, где клиент много писал.
3. На сервере (опционально):
   ```bash
   cd /root/AIServer
   ./scripts/knowledge-feedback-export.sh
   ```
   Файл `prompts/knowledge/feedback-export.json` — для себя, **не в GitHub**.
4. Запишите 3–5 частых вопросов → допишите `faq.md`.
5. Удалите `feedback-export.json`.
6. Раздел 6.

## Если что-то сломалось

| Проблема | Что проверить |
|----------|----------------|
| Бот отвечает по-старому | Забыли раздел 6? |
| «Ошибка связи» в виджете | `docker compose ps`, `curl http://127.0.0.1:3101/health` |
| Скрипты не запускаются | `sed -i 's/\r$//' scripts/*.sh` |
| Нет папки / git | Вы в `/root/AIServer`? `git pull`? |
| Долго думает / обрыв | nginx: для `/intake/` timeout 300s (см. `nginx/hestia-zz-agent-webui.conf.example`) |
